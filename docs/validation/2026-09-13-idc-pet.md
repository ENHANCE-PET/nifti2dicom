## Independent round-trip method

1. Read original DICOM with pydicom. Group by `FrameReferenceTime`, independently
   of the package's native PET `ImageIndex` grouping, then order slices using
   the source orientation and patient-space position. Check the two groupings
   agree and form complete spatial stacks with increasing timepoints.
2. Decode each plane into activity concentration using its own source rescale
   slope and intercept. Construct a float64 NIfTI from those values and the
   source physical grid; assert the saved NIfTI preserves every input value.
3. Leave NIfTI temporal units unknown: a single `pixdim[4]` cannot describe
   these variable-duration schedules. Keep the full original frame times and
   durations in the QA report and use the original DICOM as reference.
4. Call the public `nifti2dicom.convert(..., kind="image")` API.
5. Decode every output voxel. Use its DICOM orientation, position and spacing
   to map it back to an independently calculated source voxel in LPS mm.
   Require complete, unique spatial/time coverage and compare actual values,
   not just dimensions, filenames, or extrema.
6. Check every output plane's reference time, duration, acquisition date/time,
   units, correction flags and applicable decay factor against that exact
   source plane. Require coherent native PET indices and dimensions.
7. Deliberately reverse each reconstructed spatial axis, and each dynamic time
   axis, without changing the expected source. Each corruption must produce
   mismatches larger than the allowed quantization error.
8. Give each dynamic case a deliberately incorrect uniform one-second NIfTI
   timing. Both conversions must raise `ReferenceError` and publish no output.

| Static RIDER | 770,048 | 0.45776926 | 0.45777051 | 0.00000334 |
| Dynamic RIDER | 24,641,536 | 27.76556301 | 27.76557632 | 0.00001479 |
| Dynamic FLT | 25,804,800 | 7.84082621 | 7.84083035 | 0 |

All **51,216,384 voxels** were checked. These intensity errors are quantization,
not exact floating-point round trips; the writer uses one 16-bit scale for the
whole volume. This test does not establish that this precision is adequate for
every quantitative PET analysis, particularly low-activity early frames.

Every deliberate spatial reversal was detected. Reversing time produced
17,836,800 mismatched voxels for RIDER and 18,758,138 for FLT. All native frame
times, variable durations and applicable decay factors survived unchanged.
The invalid uniform-timing cases failed cleanly without publishing output.

## Permanent orientation regressions

[`tests/test_orientation_roundtrip.py`](../../tests/test_orientation_roundtrip.py)
adds 288 end-to-end conversions: all 48 signed spatial permutations, in 3D and
4D, for CT, MR and PET. The phantom has unequal spatial dimensions, anisotropic
spacing, an oblique plane, an offset origin, and a unique value encoding each
voxel's X/Y/Z/time identity. Storage permutations and flips change the data and
affine together; the expected physical phantom never changes.

Reference filenames and InstanceNumber run backwards. PET uses unequal frame
durations, slice-specific reference times and distinct decay factors. Output
expectations use DICOM geometry and the original phantom affine, not package
readers or geometry helpers. Five additional mutation tests prove that the
oracle rejects X/Y pixel reversals, exchanged Z planes, reversed temporal pixels
and reassigned temporal metadata.

Fresh local verification: **597 tests passed**, including all 293 new cases;
Ruff lint/format and mypy passed. Conversion used Python 3.13.3, numpy 2.4.2,
nibabel 5.4.0 and pydicom 3.0.1. No production conversion code changed in this
validation pass.

## Initial external IOD validation: metadata defect

Every generated instance was checked using unmodified dicom-validator 0.9.0
against DICOM 2026c in a separate Python 3.12.11/pydicom 3.0.2 environment.
Neither output files nor the validator/specification were patched for a pass.

| Case | Passed files | Errors | Finding |
| --- | ---: | ---: | --- |
| Static RIDER | 0 / 47 | 94 | Empty item inside RadiopharmaceuticalCodeSequence: missing meaning and code |
| Dynamic RIDER | 1,504 / 1,504 | 0 | No IOD errors |
| Dynamic FLT | 0 / 1,575 | 1,575 | Coding scheme and meaning present, but no code value |

Direct source-header inspection and separate validation of a source instance
from each case confirmed the same incomplete tracer-code entries. The current
writer deep-copies RadiopharmaceuticalInformationSequence, including these
malformed nested entries. The validator reports missing URNCodeValue because
neither of the alternative code-value fields is present; this is **not** a
requirement to manufacture a URN.

RadiopharmaceuticalCodeSequence is optional Type 3 under
[DICOM PS3.3 C.8.9.2](https://dicom.nema.org/medical/dicom/current/output/chtml/part03/sect_C.8.9.2.html).
Recommended bounded follow-up: omit only incomplete optional copied tracer-code
sequences with an explicit warning, retain complete codes and all other isotope
and quantitative metadata, and never guess missing codes or modify source files.
This fix has **not** been implemented in this validation pass.

The publication pipeline does not currently detect this nested-code defect.
Its internal pixel/read-back checks can therefore succeed for these outputs
even though external IOD validation fails. Keep this as a release blocker.

`dciodvfy` was not run on these public cases: the cached tool is on LMU, which
was unreachable. Earlier LMU dciodvfy results do not apply to these new files.

## Reproduction artifacts and limits

Local QA artifacts (temporary, outside the repository):

```text
/private/tmp/nifti2dicom-public-discovery.n11yiO/
  pet_manifest.json          # public selection, sizes, UIDs and attribution
  download_pet.py            # guarded download of the three selected series
  pet_roundtrip.py           # independent fixture construction and voxel audit
  validate_pet.py            # unmodified current-standard validation
  dicom/                    # untouched downloaded source instances
  nifti/                    # derived fixtures, including wrong-timing cases
  outputs/                  # generated DICOM series
  reports/                  # per-case audit, hashes and per-instance validation
```

The JSON summary records the script and standard-definition hashes. These
local temporary artifacts are not a permanent data-hosting service. To fetch
the same public cases elsewhere, install idc-index in an isolated environment
and use `IDCClient.download_from_selection` with the recorded SeriesInstanceUIDs.

No spatial/time flip was detected **within this tested scope**. The package
preserves input NIfTI temporal order; it cannot prove an upstream tool did not
already reorder volumes when per-frame provenance is absent. Likewise, a
preexisting incorrect NIfTI spatial affine cannot be diagnosed from pixels
alone. Matching dimensions are never proof of correct identity or orientation.

Still untested here: actual target-viewer/PACS orientation and cine behavior,
other scanner vendors, genuine 4D MR/CT, enhanced or gated PET, upstream temporal
sidecar reconciliation, and quantitative acceptability of the chosen scale.
